AMM7 boundary condition generation — runbook#

Same layout and workflow as NSe (see NSe/BOUNDARY_GENERATION.md for the full rationale/history this pattern comes from) — this file only covers what’s specific to AMM7.

0. The boundary point file — read this first#

Canonical copy: AMM7/Bathymetry/amm7_bdy_lonlat.txt (701 points). It lives alongside the other grid/mask artifacts under AMM7/Bathymetry/ (moved there from the old shared oceanicu_3d/Bathymetry/ directory 2026-10-22, matching NSe’s own per-area convention — see below), not the YAML domain configs in AMM7/config/.

This file is a generated artifact — never hand-edit it. The single source of truth is AMM7/config/amm7_bdy_segments.yaml, a short list of 5 segments (index form: side/l/mstart/mstop) transcribed directly from amm7_from_oceanicu.yaml’s own known-good open_boundaries: block — a restatement of what was already running, not a reinterpretation. Both the point file and the open_boundaries: block are derived from that one file, so they can’t silently diverge (same reasoning as NSe’s own nse_bdy_segments.yaml — see that area’s doc for the 2026-08-03 “123 points silently on land” incident this design exists to prevent).

Generating/verifying it — pygetm-config boundaries-generate/boundaries-check-points#

conda activate pygetm
pygetm-config boundaries-generate \
  --domain AMM7/config/amm7_from_oceanicu.yaml \
  --segments AMM7/config/amm7_bdy_segments.yaml \
  --bdy-lonlat-out AMM7/Bathymetry/amm7_bdy_lonlat.txt \
  --apply-to AMM7/config/amm7_from_oceanicu.yaml \
  --report /tmp/amm7_boundaries.md \
  --data-root BATHYMETRY_FOLDER=AMM7/Bathymetry

This calls pygetm’s own real add_by_index/adjust_mask under the hood, so a segment that’s on land, overlaps another, or crosses another fails loudly here, with the offending segment named — instead of silently writing a bad point file. --apply-to patches amm7_from_oceanicu.yaml’s own open_boundaries: list in place (by position), preserving each segment’s existing type_2d/type_3d unless --update-types is also given.

Run this after every bathymetry regeneration:

pygetm-config boundaries-check-points \
  --domain AMM7/config/amm7_from_oceanicu.yaml \
  --lonlat AMM7/Bathymetry/amm7_bdy_lonlat.txt \
  --data-root BATHYMETRY_FOLDER=AMM7/Bathymetry

Exits non-zero and prints every ON LAND: lon lat point if the current bathymetry has moved any boundary point onto land.

2026-10-22 generation: 701 points, 0 on land — clean on the first real run against the current amm7_topo_getm.nc.

If a segment needs to move, shrink, or be dropped#

  1. Edit AMM7/config/amm7_bdy_segments.yaml — change the relevant segment’s index tuple (or use guide-point form, lonlat_a/lonlat_b, for an easier-to-pick-by-eye new segment).
  2. Re-run pygetm-config boundaries-generate (above) to regenerate both amm7_bdy_lonlat.txt and the open_boundaries: block together.

Atlantic Margin Model 7 km (AMM7)#

Domain Description#

AMM7 is a regional ocean model covering the northwest European continental shelf, from the Iberian Peninsula in the south to the Norwegian Sea in the north. It encompasses the North Sea, English Channel, Celtic Sea, Bay of Biscay, and the shelf break into the northeast Atlantic.

Geographic Coverage#

  • Latitude: 40.1°N to 64.9°N
  • Longitude: 19.8°W to 12.9°E
  • Resolution: ~1/12° spherical grid (~7 km)
  • Vertical: 40 generalised vertical coordinate (GVC) levels

Key Features#

  • Bathymetry from GEBCO with Beckmann–Haidvogel smoothing
  • Open boundaries driven by CMEMS NWS AMM7 MY reanalysis (historical) or CMIP6 delta-change (future projections)
  • Rivers from EMORID (historic) or CMIP6 (future)
  • Tidal forcing from TPXO9-atlas (13 constituents)

Bathymetry#

Bathymetry#

Regridded conservatively from GEBCO onto the AMM7 ~1/12° spherical grid using bathymetry-regrid (ocean-prep), with Beckmann-Haidvogel smoothing (rx0 ≤ 0.2). Output: amm7_topo_getm.nc with variables lon, lat, mask, H.

Boundary Conditions#

CMEMS historical boundaries (T, S, SSH, currents)#

NWS AMM7 MY reanalysis (1993–present) providing hourly barotropic and daily baroclinic boundary conditions. Processed with ocean-prep run_cmems_boundaries.

Tidal boundaries (TPXO9 + CMIP6 mean SSH / barotropic transport)#

TPXO9-atlas (13 constituents) tidal prediction for zos, uo, vo combined with CMIP6 monthly mean sea-surface height and depth-integrated barotropic transport. Scenario-specific; see Scenario Summary table below.

3-D delta-change boundaries (T, S and optionally currents)#

Future 3-D boundary conditions via the delta-change method: AMM7 historical CMEMS reference cycled over the output period, with a CMIP6 monthly change signal (future 20-yr climatology minus historical 1985–2014 climatology) added at each boundary point. Scenario-specific; see Scenario Summary table below.
