NS boundary condition generation — runbook#

Same layout and workflow as NSe (see NSe/BOUNDARY_GENERATION.md for the full rationale/history this pattern comes from) — this file only covers what’s specific to NS.

0. The boundary point file — read this first#

Canonical copy: NS/Bathymetry/ns_bdy_lonlat.txt (69 points). It lives alongside the other grid/mask artifacts under NS/Bathymetry/ (moved there from the old shared oceanicu_3d/Bathymetry/ directory 2026-10-22, matching NSe’s own per-area convention).

This file is a generated artifact — never hand-edit it. The single source of truth is NS/config/ns_bdy_segments.yaml, a short list of 4 segments (index form: side/l/mstart/mstop) transcribed directly from ns_from_oceanicu.yaml’s own known-good open_boundaries: block — a restatement of what was already running, not a reinterpretation.

Generating/verifying it — pygetm-config boundaries-generate/boundaries-check-points#

conda activate pygetm
pygetm-config boundaries-generate \
  --domain NS/config/ns_from_oceanicu.yaml \
  --segments NS/config/ns_bdy_segments.yaml \
  --bdy-lonlat-out NS/Bathymetry/ns_bdy_lonlat.txt \
  --apply-to NS/config/ns_from_oceanicu.yaml \
  --report /tmp/ns_boundaries.md \
  --data-root BATHYMETRY_FOLDER=NS/Bathymetry

Run this after every bathymetry regeneration:

pygetm-config boundaries-check-points \
  --domain NS/config/ns_from_oceanicu.yaml \
  --lonlat NS/Bathymetry/ns_bdy_lonlat.txt \
  --data-root BATHYMETRY_FOLDER=NS/Bathymetry

2026-10-22 generation: 69 points, 0 on land — clean on the first real run against the current bathymetry_ns.nc (read via the DomainSnapshot domain method — see that file’s own header comment for why NS/ENA4/ENA8 use this instead of AMM7/NSe’s plain BathymetryFile).

If a segment needs to move, shrink, or be dropped#

  1. Edit NS/config/ns_bdy_segments.yaml — change the relevant segment’s index tuple (or use guide-point form, lonlat_a/lonlat_b).
  2. Re-run pygetm-config boundaries-generate (above) to regenerate both ns_bdy_lonlat.txt and the open_boundaries: block together.

1. The rest of the pipeline — not yet set up for NS#

Unlike NSe, NS does not yet have its own ocean-prep-side configs (ns_bdy_create.yaml, ns_tidal_bdy.yaml, ns_delta_bdy.yaml) — see the Data Sources page / NS/metadata.yaml’s own input_generation entries. North Sea (NS)#

Domain Description#

The NS domain is a high-resolution configuration of the North Sea and adjacent shelf seas, spanning from the English Channel in the south to the Norwegian Trench in the north, and from the eastern Atlantic shelf break to the Danish and German Bight.

Geographic Coverage#

  • Latitude: 48.5°N to 60.8°N
  • Longitude: 5.1°W to 13.4°E
  • Resolution: ~1/20° spherical grid (~5 km)
  • Vertical: 40 generalised vertical coordinate (GVC) levels

Key Features#

  • Strong tidal dynamics with M2 amplitudes up to 3 m in the Southern Bight
  • Seasonal stratification in the central and northern North Sea
  • Significant freshwater influence from Rhine, Elbe, Thames, and Scottish rivers
  • Norwegian Trench provides the deepest bathymetry (~700 m)
  • Open boundaries driven by AMM7 CMEMS reanalysis (historical) or CMIP6 delta-change (future projections)

North Sea Modeling Area#

Domain Description#

The North Sea domain covers the northwest European shelf seas, including the North Sea, English Channel, and adjacent waters.

Geographic Coverage#

  • Latitude: 50°N to 62°N
  • Longitude: 5°W to 13°E
  • Resolution: 7km horizontal, 35 sigma levels
  • Depth range: 0 to 700m

Key Features#

  • Strong tidal dynamics with M2 amplitudes up to 3m
  • Seasonal stratification in central and northern regions
  • Significant freshwater influence from Rhine, Elbe, Thames
  • Important for fisheries, shipping, and offshore wind energy

Bathymetry#

Bathymetry showing the shallow southern North Sea (<50m) and deeper Norwegian Trench (>300m)

Scientific Focus#

  • Tidal dynamics and energy dissipation
  • Seasonal stratification and mixing
  • Freshwater plumes and coastal processes
  • Storm surge prediction

How Input Files Were Generated#

Future ocean boundary conditions use CMIP6 model output as the climate-change signal on top of the historical CMEMS AMM7 reference.

Bathymetry#

Bathymetry#

Regridded conservatively from GEBCO 2025 onto the NS ~1/20° spherical grid using bathymetry-regrid (ocean-prep), with Beckmann-Haidvogel smoothing (rx0 ≤ 0.2). Output: bathymetry_ns.nc with variables lon, lat, mask, H.

NS bathymetry config

bathymetry-regrid --config config/northsea_1d20deg_bathy_create.yaml

Boundary Conditions#

CMEMS historical boundaries (T, S, SSH, currents)#

AMM7 NWS MY reanalysis providing hourly barotropic and daily baroclinic boundary conditions for the historical period. Processed with ocean-prep run_cmems_boundaries.

NS CMEMS boundary config

Config not yet committed.

run-cmems-boundaries --config config/ns_bdy_create.yaml

Tidal boundaries (TPXO9 + CMIP6 mean SSH / barotropic transport)#

TPXO9-atlas (13 constituents) tidal prediction for zos, uo, vo combined with CMIP6 monthly mean sea-surface height and depth-integrated barotropic transport. Scenario-specific; see Scenario Summary table below.

NS tidal boundary config

Config not yet committed.

run-tidal-boundaries --config config/ns_tidal_bdy.yaml

3-D delta-change boundaries (T, S and optionally currents)#

Future 3-D boundary conditions via the delta-change method: AMM7 historical CMEMS reference cycled over the output period, with a CMIP6 monthly change signal (future 20-yr climatology minus historical 1985–2014 climatology) added at each boundary point. Scenario-specific; see Scenario Summary table below.

NS delta-change boundary config

Config not yet committed.

run-delta-boundaries --config config/ns_delta_bdy.yaml --scenario ssp370

Initial Conditions#

Initial conditions (temperature, salinity)#

Monthly snapshots (1st of each month) from CMEMS NWS AMM7 MY reanalysis. Flood-fill propagates valid values into any remaining NaN cells on the model grid.

NS initial conditions config

Config not yet committed.

download-init-conditions --config config/ns_init_create.yaml --source AMM7 --year 2015
