Data Quality Checks#

Three sibling pre-production sanity-check scripts, one per forcing pipeline, built in ocean-prep/cli/. Each is a final, automated check against the real on-disk production data before it’s trusted for a run — not a replacement for a real pygetm dry-run or a short real simulation, but a check an automated tool can run in minutes that already found several real, independent bugs that would otherwise have surfaced as an odd-looking plot deep into a production run.

ScriptChecksReport
final_boundary_check.pyBio boundary conditions (no3/po4/si/o2/dissic/talk)Bio Boundary QA Report
river_final_check.pyRiver discharge (Q) and nutrient tracersRiver Discharge & Nutrient QA Report
meteo_final_check.pyBias-corrected CMIP6 meteo forcing (tas/huss/uas/vas/psl/pr + radiation)CMIP6 Meteo Forcing QA Report

Each writes a REPORT.md with findings tables and a handful of diagnostic plots — the three linked reports above are republished copies of the latest real run against production data on bb-server1.

Running them yourself#

cd ocean-prep
python3 cli/river_final_check.py --out-dir /tmp/river_check_report
python3 cli/meteo_final_check.py --out-dir /tmp/meteo_check_report
python3 cli/final_boundary_check.py --out-dir /tmp/boundary_check_report

All three default to the real production data paths (/data/EMORID, /data/BiasCorrected, /data/OceanICU/oceanicu_3d/data/NSe/CMIP6) and all 3 models x 2 scenarios; narrow with --models/--scenarios for a faster, targeted run.

What they’ve already found#

Both real findings below were investigated to a confirmed root cause and fixed (2026-10-25) — kept here as the concrete case for why these checks exist, not as an open problem list.

  • River discharge mass loss (GFDL-ESM4 daily files) — not a code bug, a stale output: the daily-disaggregated river files hadn’t been regenerated after a later update to their own monthly source. Fixed by re-running river-projection --disaggregate. See the river report for the full trace.
  • rsus/rlus radiation blow-up (up to ~1.1e6 W/m2) — a real numerical bug in the shared QDM bias-correction kernel (lib/bias_correction/ algorithms.py’s _qdm_1d): dividing by a near-zero-but-nonzero historical quantile value at a true physical zero-crossing (dawn/dusk for upward radiation). Fixed with a scale-relative epsilon guard. See the meteo report for the full trace.

The bio boundary pipeline’s own latest run found no problems — see the boundary report.

Also caught and still outstanding: 155 Danish EMORID river stations go to exactly zero discharge for the last two years of the real record (flagged “interpolated”, not “missing” — a flag-based filter alone wouldn’t catch it). See the river report’s own Zero-flow-tail section.
