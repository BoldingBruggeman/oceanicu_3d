Root-cause diagnostics — isolated reproductions

Which code path is actually leaking?

1. Meteo interpolation (read path) — isolated test

Built the real HorizontalInterpolation + TemporalInterpolation pipeline for all 10 raw CMIP6 files against the real NSe target grid (30×40 → 251×257 cells, ~54× upsampling), then drove it directly with .update(time) every 3 simulated hours — no hydrodynamics, no output, just repeated reads. 3,200 iterations = 32,000 total update calls, spanning 400+ simulated days.

Verdict: clean. RSS oscillates in a tight 752–799 MB band with zero net drift across the entire run. The meteo read path does not leak.

2. Historical → ssp126 file boundary crossing

Same pipeline, fine-grained sampling every single 3-hour step (not every 200) across 2014-12-20 → 2015-01-10, to catch what happens exactly when Concatenate first touches the scenario file.

Verdict: real, but tiny and one-time. A genuine +56 MB step exactly at 2015-01-01 00:00 (both files' handles/metadata now held at once), then a stable new plateau — not an ongoing leak, and far too small (56 MB) to explain a multi-GB decline.

3. Output writing (netCDF4/HDF5 unlimited time dimension) — isolated test

Standalone netCDF4 file, unlimited time dimension, 4 variables (2× 3D, 2× 2D, smaller grid than production to isolate the mechanism cheaply), sync() every write matching production's sync_interval: 1. 10,000 sequential writes.

Verdict: real, monotonic growth — the strongest lead. RSS climbs 50.8→128.2 MB over ~8,500 writes, then plateaus flat. Unlike the meteo path, this is genuine sustained growth, not oscillation. Production fields are ~18× larger per 3D variable across several files and many more timesteps — if the ceiling scales with variable size × chunk count, it could plausibly sit in the multi-GB range, meaning Experiment 1's decline may be the ramp-up portion of a much higher plateau. Not yet confirmed at production scale.
